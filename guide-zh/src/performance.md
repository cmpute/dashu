`dashu` 的目标是在保持可移植性的同时兼顾效率。默认情况下，它为每个目标架构的通用基线进行编译，因此依赖 `dashu` 的二进制文件可以在目标基线支持的任何 CPU 上运行。

当大数运算位于热路径时，通过告诉编译器你实际运行的 CPU，可以获得显著的加速。

## 使用 `target-cpu=native` 构建

影响最大的单一设置是使用宿主 CPU 的特性集进行编译：

```sh
RUSTFLAGS="-C target-cpu=native" cargo build --release
```

这让 LLVM 在**整个** crate 中使用 CPU 的完整指令集。例如在现代 x86-64 处理器上，它会启用 `bmi1`/`bmi2`（无标志位的 `mulx` 宽化乘法）、`adx`（`adcx`/`adox` 进位链）、`avx2` 和 `fma`，从而加速库中内部的乘法、平方和加法内核。这比 `dashu` 自身应用的运行时特性检测（见下文）严格更广泛且更快。

要使此设置对项目永久生效，将其添加到 `.cargo/config.toml`：

```toml
[build]
rustflags = ["-C", "target-cpu=native"]
```

> **可移植性提示：** 使用 `target-cpu=native`（或固定的 `x86-64-v3`）构建的二进制文件，在缺乏这些特性的旧 CPU 上会因非法指令而崩溃。请在部署到已知的新硬件上时使用此选项。
> `dashu` 本身作为发布的库，始终保持可移植的默认值——`target-cpu` 的选择权在你，即下游用户。
>
> 如果你想在获得大部分加速的同时保持与较新硬件的兼容性，`-C target-cpu=x86-64-v3` 是一个好的固定替代方案（它假设 Haswell 时代 / Excavator 时代或更新的 CPU）。

注意 `target-cpu=native` 针对的是**构建机器**的 CPU。如果你在一台主机上构建并部署到另一台机器上，请使用与部署硬件匹配的显式 `target-cpu`/`target-feature`。

## 运行时特性检测（默认构建）

即使在默认的基线构建中，当宿主 CPU 支持时，`dashu-int` 中最热的基数情况乘法内核也会在运行时分派到 BMI2（`mulx`）实现（需要 `std` 特性）。因此，一个可移植的基线二进制文件在那些内核上已经能在现代 CPU 上利用 `mulx`，无需任何额外配置。

不过，这只覆盖了选择加入运行时检测的特定内核。如上所述使用 `target-cpu=native` 构建会将优化应用到**所有地方**，因此它总是至少同样快，并且在你能控制构建时是推荐的选择。
