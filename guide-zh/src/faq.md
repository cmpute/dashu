## 为什么这个库叫 `dashu`？

`dashu` 是"大数"（"dà shù"）的拼音罗马化。

<p align="center">
  <img src="./assets/dashu-logo.png" alt="dashu 标志：一棵风格化的榕树" width="200">
</p>

标志是一棵风格化的**榕树**——"大树"（"dà shù"）的原型形象。这是一个双关：大树（*big tree*）和大数（*big number*，即库的名字）在普通话中是同音词，因此一棵大树在视觉上代表了名字背后的"大数"。下垂的线条是榕树标志性的[气根](https://en.wikipedia.org/wiki/Aerial_root)。

## 为什么要使用 `dashu`？

`dashu` 的目标是成为 GNU GMP + MPFR + MPC 的 Rust 原生、符合人体工程学的替代品：任意精度整数、浮点数、有理数和复数，全部用纯 Rust 实现，完整支持 `no_std`，并提供任意基数的浮点数。

与其他 Rust crate 的对比：

| Crate | 纯 Rust | 完整 `no_std` | 整数 | 浮点数 | 有理数 | 复数 |
|-------|-----------|---------------|-----|-------|-------|---------|
| **dashu** | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `num-bigint` | ✓ | ✗ | ✓ | ✗ | ✗ | ✗ |
| `ibig` | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ |
| `rug` | ✗ (C/GMP) | ✗ | ✓ | ✓ | ✓ | ✓ |

`malachite` 也提供以性能为导向的纯 Rust 整数和有理数，但是面向 `std` 的，并且不涵盖任意精度浮点数或复数。与 `rug` 不同，`dashu` 没有 C 依赖——它在 Rust 能运行的任何地方构建和运行，包括 `no_std` 目标。

## 已知限制

- **没有 NaN。** 无效运算在便捷层会 panic，在上下文层返回 `Err(FpError)`。无穷是终态值，不是操作数——参见[标准合规性](./compliance.md)。
- **正确舍入的超越函数。** 实超越函数——`exp`、`exp_m1`、`ln`、`ln_1p`、三角与双曲函数族、`hypot`、`powi`、`powf`——均通过 Ziv 重试循环保证正确舍入。`dashu-cmplx` 的复数超越函数（`exp`、`log`、`powf`、`powi`、`sin`/`cos`/`tan`/`sin_cos`、`asin`/`acos`/`atan`、`sqrt`）经由其自身的 Ziv 循环正确舍入，同时认证实部与虚部；`tan` 采用免消去的双角公式（对所有有限 `|Im z|` 精确），`asin`/`acos` 采用因式分解的 $1-z^2=(1-z)(1+z)$（在 $z = \pm 1$ 处亦精确）。
- **复数功能覆盖。** `CBig` 提供域运算和基本超越函数；复数双曲函数、`fma` 及其他若干功能推迟到 0.5.x（参见 v0.5 版本说明）。
- **没有球体/区间运算。** 与 MPC 的实验性 `mpcb_t`（复数球体）不同，`dashu` 不提供区间或球体类型。这是一个刻意的范围选择：球体运算在上游仍是实验性的，如果/当它稳定后，最好由一个**独立的 crate** 在 `dashu-float`/`dashu-cmplx` 之上提供，而非耦合到核心类型。
- **尚无 SIMD-FFT 乘法**（计划在 v1.0 中实现）。

## MSRV 与特性策略

当前 MSRV 为 **1.68**。第三方集成遵循带版本号的特性约定：稳定的依赖使用 `xxx_vYY`（例如 `rand_v08`），并附带一个指向某一版本的未编号 `xxx` 别名；而不稳定的依赖将 `xxx` 别名指向最新版本。完整解释请参阅 [Cargo 特性](./index.md#cargo-特性)。
